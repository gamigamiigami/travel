# Yahoo!トラベル スペシャルクーポン ウォッチャー v2

Edge と Chrome で Yahoo!トラベルを自動で散策し、**スペシャルクーポン**（1,000 / 2,000 /
3,000 / 5,000 / 50,000円OFF など）が出たら**スマホとPCの両方に通知**します。
あわせて全チェック結果をCSVに残し、**曜日別・時間帯別・ブラウザ別の出現率**を
集計できます。

---

## 1. 調べたこと（スペシャルクーポンの仕様）

公式には抽選ロジックが公開されていないため、公開情報からわかった範囲です。

| 項目 | わかっていること |
|---|---|
| 出現の仕方 | サイトにアクセスした瞬間、画面右側などにポップアップで**自動獲得型**として出る |
| 金額 | 1,000円 / 2,000円 / 3,000円 / 5,000円 など。まれに高額枠もある |
| 対象 | 公式が「**対象者の方にのみ表示します**」と明記。**全員が出せるものではない** |
| 有効期限 | 表示から **60分 / 90分 / 180分** の時間限定。過ぎると予約途中でも使えない |
| 配布条件 | 配布期間・時間帯・条件はすべて非公開 |
| 出やすいと言われる状況 | ①複数回・数日にわたって訪問している ②1泊5万円クラスの高級宿など、具体的に宿を検索している |

**このツールの設計はこの点に直結しています。**

- 有効期限が最短60分 → **見逃さないためのリアルタイム通知**（これが本命の価値）
- 「何度も訪れる」→ ランダムな間隔で繰り返し巡回する
- 「具体的に宿を調べる」→ **宿の詳細ページまで潜る**
- Edge / Chrome で抽選が別枠の可能性 → **ブラウザごとに別プロファイル**で回す
- 噂が本当かどうか → **全チェック結果をCSVに残して自分で検証する**

> ⚠️ 抽選である以上、動かせば必ず出るものではありません。
> 「出たときに確実に気づける」ことが実際の効果です。

## 2. 仕組み

### クーポンの検出（3層 × 全フレーム）

DOM構造は非公開で頻繁に変わるため、単一のCSSセレクタには賭けていません。
また **iframe の中も走査します**（ポップアップがiframeだと本文テキストに出ないため）。

1. **ネットワーク層** — ページが裏で叩くAPIのJSONを覗き、クーポンらしきオブジェクトから
   金額とコードを抜く。見た目が変わっても壊れにくい。
2. **ポップアップ層** — `[role=dialog]` / `[class*=oupon]` / `[class*=odal]` など
   10種類のセレクタを全フレームで総当たりし、中のテキストを**緩めの条件**で判定。
3. **ページ全体層** — 各フレームの全文を、**強いキーワードが金額の近くにあること**を
   条件に判定。宿の価格をクーポン額と誤認しないための仕掛け。

### 「どれくらいクーポンらしいか」を点数で出す

検出は2つの関門を両方通ったものだけを採用します。

1. 金額がクーポン系キーワードの**近く（±160文字）**にあること
2. 周辺テキストの**スコアがしきい値以上**であること

| 加点要素 | 点 |
|---|---|
| 「スペシャルクーポン」 | +5 |
| 「限定クーポン」「あなただけのクーポン」 | +4 |
| 「クーポンを獲得/ゲット/もらう」 | +3 |
| 「時間限定」「今だけ」 | +3 |
| 残り分数の表記（**60分 / 90分 / 180分すべて**） | +4 |
| 「◯◯円OFF」形式 | +2 |
| クーポンコードらしき英数字 | +2 |
| 「クーポン」単独 | +1 |

通知には**点数と根拠**が載るので、誤検出したとき何が効いたのかがすぐ分かります。

```
🎫 5,000円OFFクーポン出現！
金額: 5,000円OFF
コード: AB12CD34
有効時間: 約60分
ページ: トップページ
検出元: popup (score=17)
根拠: スペシャルクーポン・獲得ボタン・60分限定・円OFF表記・クーポンコード
```

### 巡回のしかた

`config.yaml` の **targets（毎回必ず見るページ）** を起点に、そこから
**リンクを辿って宿の詳細ページまで潜ります**。「決め打ちのページを確実に見る」と
「毎回違うページを見る」の両立です。

### 安全装置

- 巡回先は `travel.yahoo.co.jp` 配下のみ。外部サイトには出て行きません
- **予約・決済・購入・キャンセル・アカウント操作系のURLは絶対に踏みません**
  （`crawl.blocked_url_patterns`。消さないでください）
- ボタンを押すのも「クーポン獲得」系の文言だけ。「予約」「決済」「確定」などの語を
  含む要素はクリック対象から除外
- 同じクーポンは既定180分（＝クーポンの有効期限）再通知しません
- **1日あたりの巡回回数に上限**があります（既定40ラウンド）

## 3. セットアップ（Windows）

### 用意するもの

- **Python 3.11 以上** — [python.org](https://www.python.org/downloads/windows/) から。
  インストール時に「**Add python.exe to PATH**」に必ずチェック
- **Microsoft Edge** と **Google Chrome**（普段お使いのものでOK。追加DLは不要）
- **ntfy アプリ** — [Google Play](https://play.google.com/store/apps/details?id=io.heckel.ntfy) / [App Store](https://apps.apple.com/app/ntfy/id1625396347)

### 手順

**① `setup.bat` をダブルクリック**

仮想環境の作成 → ライブラリ導入 → `config.yaml` と `.env` の作成 → 設定確認まで自動です。
途中でメモ帳が開きます。

**② `.env` に通知先を書く**

```
NTFY_TOPIC=yahoo-coupon-r7k2m9x4qz
```

> 🔑 **トピック名は事実上のパスワードです。** 名前を知っている人は誰でもその通知を
> 読めるので、`yahoo-coupon` のような推測しやすい名前は避け、ランダムな文字を
> 混ぜてください。

スマホの ntfy アプリで「＋」→ 同じトピック名を購読すれば準備完了。
既定では**スマホ通知（ntfy）＋ PCのトースト通知**の二段構えで届きます。

<details>
<summary>メール / Discord で受け取りたい場合</summary>

`.env` に値を入れて、`config.yaml` の `notify.providers` に足すだけです。

```yaml
notify:
  providers: [ntfy, windows, email]
```

```
EMAIL_USERNAME=あなた@gmail.com
EMAIL_PASSWORD=アプリパスワード16桁
EMAIL_TO=あなた@gmail.com
DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/...
```

Gmail は通常のパスワードでは送信できません。2段階認証を有効にした上で
「アプリパスワード」を発行してください。なお**メールは配信が数分遅れることがあり、
60分限定クーポンでは不利**です。
</details>

**③ `test-notify.bat`** — スマホとPCに通知が届けばOK

**④ `login.bat`（初回だけ）**

Edge → Chrome の順にウィンドウが開きます。

1. 各ウィンドウで Yahoo! JAPAN にログイン
2. 「**ログイン状態を保持する**」はONのまま
3. できたらコンソールで Enter

ログイン情報は `profiles/edge` と `profiles/chrome` に保存され、**以降は再ログイン不要**です。
普段使いのブラウザとは別プロファイルなので、ツールが動いていても普段の Edge / Chrome は
そのまま使えます。

**⑤ `run.bat`** — あとは放置

## 4. PC起動時に自動で動かす（常駐）

1. `config.yaml` の `crawl.headless` を `true` に（ウィンドウが出なくなります）
2. タスクスケジューラ →「基本タスクの作成」
3. トリガー：「**ログオン時**」
4. 操作：「プログラムの開始」
   - プログラム： `wscript.exe`
   - 引数： `"C:\パス\travel\run-hidden.vbs"`
   - 開始： `C:\パス\travel`
5. プロパティで「**タスクを実行するためにスリープを解除する**」をONにすると
   取りこぼしが減ります

## 5. 出現傾向を見る

`stats.bat` を実行すると、貯まったデータを集計します。

```
===== スペシャルクーポン出現傾向 =====
集計期間      : 2026-09-02 〜 2026-09-05 (4日)
総チェック回数: 180
検出回数      : 9 (5.00%)

-- ブラウザ別 --
  区分              チェック     検出       出現率
  chrome                90       5     5.56%
  edge                  90       4     4.44%

-- 時間帯別 --
  区分              チェック     検出       出現率
  07時台                 9       2    22.22%
  ...
```

検出しなかった回も記録しているので、**分母つきの出現率**が出ます。
「Edgeのほうが出やすい」「夜のほうが出やすい」を自分のデータで検証できます。

> ⚠️ 検出30件くらいまでは差はほぼ偶然の範囲です。レポートにもその旨が出ます。

元データは `data/history.csv` なので、Excelで開いて自由に分析もできます。

## 6. 誤検知・未検知を直す

Yahoo!トラベルの画面は変わります。うまく動かないときは:

```bat
:: 実際のページを保存する（クーポンが出た瞬間に Enter）
.venv\Scripts\python -m yahoo_coupon_watcher capture --browser edge

:: 保存したファイルで検出ロジックを試す（点数と根拠が出ます）
.venv\Scripts\python -m yahoo_coupon_watcher scan-file data\captures\20260909-120000_edge.txt
```

- **通知が多すぎる** → `detect.min_score_page` を上げる（7 → 9 など）。
  または `detect.ignore_patterns` にその文言を足す／`amounts_whitelist` で金額を絞る
- **出たのに通知されない** → `detect.min_score_popup` を下げる（4 → 3）。
  `capture` のテキストを見て、文言が `detector.py` の `SCORE_RULES` にあるか確認
- **クーポンが出たページが分かった** → `config.yaml` の `crawl.targets` に足す。**これが一番効きます**
- 動きを見たい → `.venv\Scripts\python -m yahoo_coupon_watcher run --once -v`

## 7. 使うときのお願い

- **巡回間隔を短くしないでください。** 既定は12〜25分に1回・1日40ラウンドまでで、
  人が熱心に宿を探しているのと同程度に収まる設計です。
- 深夜（既定1時〜7時）は自動で停止します。
- 自分のアカウントで自分の分の抽選を回すための個人用ツールです。複数アカウントの
  併用や転売目的での利用は想定していません。
- Yahoo!トラベルの利用規約・仕様変更により使えなくなる可能性があります。自己責任でどうぞ。
