# ブラウザ拡張版（インストール不要）

Python も Playwright も要りません。**ダウンロードは0**で、いま使っている
Edge / Chrome の中で直接動きます。

## なぜこちらが有利か

Python版は「ツール専用の新しいブラウザプロファイル」で巡回します。つまり
**まっさらな新規ユーザーとして抽選に参加している**状態です。

拡張版は**あなたが普段使っているプロファイルの中**で動きます。履歴もCookieも
積み上がった状態で抽選に参加できるうえ、**あなたが普段Yahoo!トラベルを見ている
最中も見張っている**ので、巡回の合間の取りこぼしがありません。

| | Python版 | 拡張版 |
|---|---|---|
| PCへのインストール | Python + Playwright（数百MB） | **なし** |
| ログイン | 専用プロファイルに1回 | **すでにログイン済みのものを使う** |
| 監視タイミング | 巡回した瞬間だけ | 巡回＋**普段の閲覧中もリアルタイム** |
| iframe内のポップアップ | 走査する | ページの中にいるので**確実に見える** |

## 入れかた（3分）

### ① フォルダを用意する

このリポジトリの `extension` フォルダを、消さない場所に置きます
（例: `C:\Users\あなた\Documents\coupon-watcher`）。
**拡張機能はこのフォルダを読み続けるので、あとから移動・削除しないでください。**

### ② ブラウザに読み込ませる

**Edge の場合**

1. アドレスバーに `edge://extensions` と入力
2. 左下の「**開発者モード**」をONにする
3. 「**展開して読み込み**」を押し、`extension` フォルダを選ぶ

**Chrome の場合**

1. アドレスバーに `chrome://extensions` と入力
2. 右上の「**デベロッパー モード**」をONにする
3. 「**パッケージ化されていない拡張機能を読み込む**」を押し、`extension` フォルダを選ぶ

> 🏢 **職場PCの方へ**：会社の管理ポリシーで開発者モードが無効化されていることが
> あります。スイッチが押せない／グレーアウトしている場合は、この方法は使えません。
> また業務PCに私用ツールを常駐させてよいかは、社内規程をご確認ください。

Edge と Chrome の両方に入れれば、**別々の抽選枠として同時に回せます**。

### ③ スマホ通知を設定する（任意だが推奨）

1. ツールバーの🎫アイコン →「設定と出現傾向」
2. 一番上に**トピック名が自動で作られている**ので「コピー」を押す
3. スマホに **ntfy** アプリを入れる（App Store / Google Play で「ntfy」）
4. アプリの「＋」→ コピーしたトピック名を貼り付け →「Subscribe」
5. 設定画面で「テスト通知を送る」を押し、スマホに届けば完了

入力するのはこの1回だけです。アカウント登録はありません。

> 🔑 トピック名は事実上のパスワードです。人に教えないでください。

PCの通知だけでよければ、この手順は丸ごと飛ばせます（既定でONです）。

## 巡回で何をしているか

「ページを開いたままでは出ない」ので、1回の巡回でこう動きます。

1. **トップページ**を開いて眺める
2. **検索窓に地名を入れて実際に検索する**（「箱根」「熱海」など20地名からランダム）
3. 検索結果から**高価格帯の宿を選んで開く**（既定：1泊25,000円以上）
4. さらに数ページ辿る（既定4ページ）

各ページで数秒〜十数秒とどまり、その都度クーポンを調べます。
「何度も訪れる」「具体的に、それも高い宿を調べる」という噂をなぞる作りです。

### 高価格帯の判定について

Yahoo!トラベルの価格絞り込みURLの仕様は公開されていないので、**検索結果に
表示されている料金を読んで**判断します。

1枚のカードに「1泊12,000円〜」と「合計24,000円」のように複数の金額が出ている
ことがあるため、**安いほうを採用**します。つまり「どう数えてもこの額以上」の宿
だけが対象になります。該当が無ければ通常どおりリンクを選びます。

金額は設定③で変更できます（優先自体をオフにもできます）。開いた宿の価格は履歴
にも残るので、**「高い宿を見たときのほうが出やすい」が本当かを後から検証できます**。

> 💡 **さらに効かせるコツ**：狙っている宿のページや、自分で高価格帯の検索を
> したときのURLを、設定③の「毎回見に行くページ」に貼っておくと、その動きを
> 毎回確実に再現できます。

## 使いかた

入れた時点で動き始めます。あとは放置してください。

- ツールバーの🎫アイコン → 見張りのON/OFF、次の巡回までの時間、直近の検出
- 「**いま巡回する**」— バックグラウンドのタブですぐ1回見に行く
- 「**このページを調べる**」— いま開いているページを手動でチェック
- 「**設定と出現傾向**」— 全設定と、曜日別・時間帯別・ブラウザ別の出現率

```

有効時間: 約60分
獲得ボタンを自動で押しました
```

PCの通知をクリックすると、そのページが開きます。

## 検出のしくみ

DOM構造は非公開で頻繁に変わるため、特定のclass名には依存しません。

**2つの関門を両方通ったものだけ**をクーポンとみなします。

1. 金額がクーポン系キーワードの**近く（±160文字）**にあること
   → 宿の価格を「クーポン額」と取り違えないため
2. 周辺テキストの**スコアがしきい値以上**であること

| 加点要素 | 点 |
|---|---|
| 「スペシャルクーポン」 | +5 |
| 「限定クーポン」「あなただけのクーポン」 | +4 |
| 「クーポンを獲得/ゲット/もらう」 | +3 |
| 「時間限定」「今だけ」 | +3 |
| 残り分数の表記（**60分 / 90分 / 180分すべて**） | +4 |
| 「◯◯円OFF」形式 | +2 |
| クーポンコードらしき英数字 | +2 |
| 「クーポン」単独 | +1 |

`all_frames` で動くので、**iframe の中に出たポップアップもそのフレーム自身が検出**します。

### 安全装置

- 巡回するのは `travel.yahoo.co.jp` 配下のみ
- **予約・決済・購入・キャンセル・アカウント操作系のURLは絶対に開きません**
- 押すボタンは「クーポン獲得」系の文言のみ。「予約」「決済」「確定」などの語を
  含む要素は、設定に関係なく**絶対に押しません**
- 同じクーポンは既定180分（＝クーポンの有効期限）再通知しません
- 1日の巡回回数に上限があります（既定40回）
- 深夜（既定1時〜7時）は自動で止まります

## 裏で何をしているか確かめる

巡回はバックグラウンドのタブで動くので、放っておくと本当に検索できているのか
分かりません。確かめる方法が2つあります。

### 巡回ログ

設定画面の「⑥ 巡回ログ」に、1手ずつ何をしたかが出ます（5秒ごとに自動更新）。
ツールバーの🎫にも直近6件が出ます。

```
14:32:10  巡回開始：トップページ
14:32:18  トップページ：クーポンなし
14:32:18  「箱根」で検索します
14:32:25  検索できました → /search/?p=箱根
14:32:33  箱根 > 検索:箱根：クーポンなし
14:32:33  リンク142件（価格が読めたもの28件／25,000円以上 9件）
14:32:33  宿を開きます（32,000円）
14:32:44  箱根 > 宿(32,000円)：クーポンなし
14:33:02  巡回終了
```

**ここを見れば一発で分かります。**

- `検索できました → /search/...` … 検索が効いている
- `検索を実行しましたが、ページが変わりませんでした` … 検索窓を掴めていない
- `価格が読めたもの 0件` … 価格の読み取りが効いていない

うまくいっていない行が出たら、そのログを教えてください。

### 巡回を目で見る

設定画面の「**巡回を目で見る（タブを表示して1回実行）**」を押すと、タブを表に
出したまま巡回します。検索窓に地名が入り、結果から宿へ移動していく様子が
そのまま見えます。1回見て納得したら、あとは裏で回してください。

## クーポンが出たのに検出されなかったとき

**そのページを開いたまま**、設定画面の「⑦ 検出されないときの診断」→
「**このページの中身を保存する**」を押してください。

メインページと**すべてのiframe**、さらに shadow DOM の中まで含めて、
ポップアップらしき要素のテキストをテキストファイルに書き出します。
これがあれば、なぜ拾えなかったのかを特定できます。

> ⚠️ ファイルにはそのページに表示されている文字がそのまま入ります。
> ログイン名などが含まれることがあるので、人に渡す前に中身を確認してください。

あわせて巡回ログに「**惜しい**」という行が出ていないか見てください。

```
15:02:11  惜しい：5,000円 を見つけましたが score=5 でしきい値7に届かず（根拠: クーポン表記・円OFF表記）
```

これが出ていれば、検出自体はできていてしきい値だけの問題です。設定④の
「しきい値：ページ全体」を下げれば拾えるようになります。

## 出現傾向を見る

設定画面の一番下に、貯まったデータの集計が出ます。

```
1,240回チェックして 12回検出（0.97％／9日ぶん）

ブラウザ別    チェック   検出   出現率
edge              620      8    1.29%
chrome            620      4    0.65%
```

**検出しなかった回も記録している**ので、分母つきの出現率が出ます。
CSVで書き出せばExcelでも分析できます。

> ⚠️ 検出30件くらいまでは、この差はほぼ偶然の範囲です。画面にもその旨が出ます。

## うまく動かないとき

| 症状 | 対処 |
|---|---|
| 通知が多すぎる | 設定④の「しきい値：ページ全体」を上げる（7 → 9）。または誤検知した文言を「無視」欄に足す |
| 出たのに通知されない | 「しきい値：ポップアップ内」を下げる（4 → 3）。金額の下限も確認 |
| 特定のページで出ると分かった | 設定③の「毎回見に行くページ」に足す。**これが一番効きます** |
| 拡張が反応しない | `edge://extensions` で「エラー」ボタンが出ていないか確認。Yahoo!トラベルのタブを再読み込み |
| 巡回タブが残っている | 見張りをOFF→ONで消えます |

## 開発者向け

```bash
node --test extension/tests/*.test.js    # 28 tests
```

| ファイル | 役割 |
|---|---|
| `src/detector.js` | 検出ロジックとスコアリング（ブラウザAPI非依存・テスト対象） |
| `src/content.js` | ページ内に常駐し、MutationObserverで監視。iframeにも入る |
| `src/background.js` | 巡回・通知・重複抑止・履歴（service worker） |
| `src/settings.js` | 設定の既定値、URLの安全判定 |
| `src/stats.js` | 出現率の集計とCSV出力（テスト対象） |
| `src/options.*` / `src/popup.*` | 設定画面とツールバーUI |
| `../tools/make_icons.py` | アイコンPNGの生成（外部ライブラリなし） |
